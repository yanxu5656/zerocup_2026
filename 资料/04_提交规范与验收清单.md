## 二、双版本规范

### 2.1 单文件版（给评审"双击即看"）

```
灯影_单文件版/
├── index.html        ← 双击这个即可
├── origin.html
├── play.html
├── people.html
└── future.html
```

- 每个 HTML **自包含**：CSS、JS、SVG 图片全部内联，无任何相对路径依赖（页面之间用相对链接互跳）。
- 目标场景：评审拿到 zip，解压后双击，不需要装任何环境、不需要起本地服务器。
- 体积上限：整包 ≤ 6 MB。

### 2.2 工程版（给评审"看代码"）

```
灯影_工程版/
├── index.html / origin.html / play.html / people.html / future.html
├── assets/
│   ├── css/  base.css  layout.css  components.css  pages.css
│   ├── js/   main.js  lamp.js  stage.js  theater.js  diy.js
│   └── img/  *.svg
├── README.md
└── 素材说明.md
```

- 目录语义清晰，CSS/JS 按职责拆分，关键逻辑有中文注释。
- 不含 `资料/`、`TEST/`、`.git/`、`node_modules/` 等非交付内容。

### 2.3 命名规范

| 对象 | 命名 |
| --- | --- |
| 单文件版目录 | `灯影_单文件版` |
| 工程版目录 | `灯影_工程版` |
| 压缩包 | `零杯2026_非遗灯影_夏思远_李健豪_廖哲煜_闫煦_单文件版.zip`<br>`零杯2026_非遗灯影_夏思远_李健豪_廖哲煜_闫煦_工程版.zip` |
| 压缩格式 | `.zip`（不用 rar/7z，评审可能用系统自带解压） |

> zip 内**必须**带一层同名根目录，避免解压后文件散落一地。

## 三、打包流程

```powershell
# 在仓库根目录执行（网站源码放在 web/ 时可用默认参数）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\pack-release.ps1 -Source web -Out dist

# 装了 PowerShell 7 的机器
pwsh -NoProfile -File tools\pack-release.ps1 -Source web -Out dist

# 如果源码就在根目录（index.html 与 assets/ 同级）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\pack-release.ps1 -Source . -Out ..\dist
```

> 源码目录根层必须有 `index.html`；脚本统一放在 `</body>` 之前，**不要用 `defer` / `async`**（单文件版内联后它们会失效，脚本会报错提醒）。

脚本会做四件事：
1. 生成单文件版（内联 CSS/JS/图片为 data URI）。
2. 生成工程版（纯复制，剔除 `资料/`、`TEST/`、`.git/` 等）。
3. 合规扫描：外链、第三方库关键字、超大文件、缺失页面。
4. 分别打 zip 并输出体积报表。

**打包后必做**：把 zip 解压到**桌面上另一个目录**再打开一遍（不要在源码目录里测，缓存会骗人）。

## 七、三分钟评审脚本（给 C 的 PPT / 路演用）

> 评委在展位停留约 3 分钟，按这个顺序讲，最省时间。

1. **0:00–0:20** 一句话：这不是一个"非遗介绍页"，是一个**能演的灯箱**。
2. **0:20–1:10** 现场点灯 → 拖三个关节通关（让评委自己上手 10 秒）。
3. **1:10–1:50** 放一段剧场，说明"我们没做 3D，用光影和剪影做出了空间感"。
4. **1:50–2:30** 翻过见人页，讲一位传承人的一句话（情绪落点）。
5. **2:30–3:00** 收尾：技术全原生、零依赖、离线可跑、手机可用；一页纸里三个数字（5 页 / 3 关 / 0 依赖）。

**不讲的**：配色为什么这样选、用了什么缓动函数、做了多少个组件。评委不关心工艺，只关心"记得住什么"。
