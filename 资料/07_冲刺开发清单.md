## 3. 三个必须先拍板的架构决策

### 3.1 双模架构：静态优先，后端增强

评委的评测方式是**解压 → 双击 index.html**，不会给你装 Node、跑 npm。所以：

```
双击打开（file://）          启动本地服务（start.bat）
      │                              │
      ├─ 全站可玩、可通关、可导出      ├─ 额外解锁：云端存档 / 排行榜 / 作品分享
      ├─ 进度存 localStorage          ├─ 数据落库（SQLite / JSON）
      └─ 检测 /api/health 失败        └─ 同一套前端，仅数据层切换
             → 静默降级，不报错
```

**铁律**：任何后端功能都必须有本地降级路径，`fetch` 失败只允许静默降级，**不许出现报错、不许阻塞主线**。

**技术选型**：Node 18+ 标准库（`node:http` + `node:fs` / `node:sqlite`），**零第三方依赖**，不需要 `npm install`。
理由：① 手册允许"成熟后台框架"但要求注明，零依赖反而更干净、更好讲；② 评委机器不装包也能跑；③ 代码审查时"没有依赖"本身就是加分叙事。

### 3.2 玩法：从"拖拽演示"到"操偶演出"

现在的三关本质是**同一个动作做三次**（拖到指定角度）。要升级的是**动词数量**与**反馈密度**：

| 层 | 现状 | 目标 |
| --- | --- | --- |
| 动词 | 1 个：拖关节 | 3 个：**抬**（关节）、**抖**（竹签，短促甩动）、**拉**（幕布 / 灯绳） |
| 手感 | 角度吸附 | 惯性 + 阻尼 + 到位"咔"感 + 反向阻力 |
| 判定 | 到角度即通过 | **时机 + 幅度**双判定：准 / 良 / 失，连击累积 |
| 反馈 | 光环 + 印章 | 光环 + 幕布震动 + 观众声浪（Web Audio 合成）+ 唱词逐字 + 结算评级 |
| 结构 | 3 关线性 | 3 出戏 × 3 折，每折一个动词主题，末折有分支结局 |
| 目标感 | 通关解锁剧场 | 戏班声望（评级累积）解锁戏服 / 剧目 / 自由演出 |

**核心循环**：听鼓点 → 看提示 → 做动作 → 看判定 → 听满堂彩 → 下一折。一轮 20 秒，三折 1 分钟，符合评委停留时长。

### 3.3 素材精度优先于功能数量

一条硬标准：**把皮影缩到 120px 宽，还认得出是皮影，不是剪影小人**。
做不到，后面所有功能都是白搭——因为"素材质量 10 分"是一眼判定的，而"功能丰富"还要试才知道。

投入顺序：皮影本体 → 剧场三场景 → 纹样 8 枚 → 工具与手部 → 装饰纹理。

## 7. 明确不做（防散）

| 不做 | 理由 |
| --- | --- |
| 用户注册 / 登录 / 权限 | 手册明确"后端不计入整体评价"，且登录会劝退评委 |
| 3D / WebGL / Three.js | 破坏零依赖，低端机掉帧，与皮影的平面美学相悖 |
| 实时多人对战 | 需要长连接与服务端权威，风险与收益完全不成比例 |
| 全站搜索 | 5 页站点，导航足够；搜索是"功能的自我感动" |
| 自绘中国地图 | 地图须用标准底图，自绘有合规风险 |
| 内嵌 webfont | 体积暴涨，且系统宋体在中文场景已够用 |
| 第 6、7 个页面 | 5 页已够，加页只会稀释每页完成度 |
